# 中国专利法速查工具箱

为三性审查与查新提供**法条依据与判定路径**。主用户：`patent-search-scout`（甄无遗）、
`patent-examiner-sim`（严三性）、`patent-attorney-writer`（权要达）。

**权威源**：`references/patent-law.md`（3739 字符，8 节）。**法条号一律以该文件核对后再写入产出**——
凭训练记忆写法条号是本 skill 要防的头号失效模式（对照 triz-matrix failure-001：高维静态知识不可信记忆）。

## 一、何时用 / 何时不用

| 场景 | 用不用 |
|---|---|
| 判定某方案是否具备新颖性/创造性/实用性 | ✅ 用 |
| 对检索到的对比文件做 X/Y/A/R/P/E 分级 | ✅ 用（分级决策树见 §三） |
| 客体合规预审（是否属于法25排除项） | ✅ 用 |
| 撰写阶段的形式缺陷自查（摘要300字、多项引多项等） | ✅ 用 |
| 撰写权项文本本身 | ❌ 不用，走 `claims-drafting` |
| 判断"能不能申请"以外的商业价值/侵权风险 | ❌ 不在本 skill 范围，需转专业法律意见 |
| 非中国专利（PCT/US/EPO）法条 | ❌ 不用——本表**仅覆盖中国专利法**，跨法域引用前必须明示标注 |

## 二、工作流（5 步，每步有明确输入/输出）

**输入**：技术方案描述（或检索到的对比文件清单）+ 申请日/优先权日（有则给，无则标注"待定"）
**输出**：一份《三性/合规性判定》，含法条号 + 判定结论 + 依据 + 待补信息清单

1. **客体预审**（法2.2 / 法5 / 法25）
   输入：技术方案 → 输出：是否属于技术方案、是否落入排除项。
   ⚠️ 排除项有例外必须同时判：疾病诊断治疗方法不授权但**药物/制剂/制药用途（Swiss型）可授权**；
   动植物品种不授权但**其生产方法可授权**。落排除项 → 直接终止后续三性判定，输出客体不合格结论。

2. **现有技术界定**（法22.2 前段）
   输入：申请日/优先权日 → 输出：现有技术的**时间边界**。
   ⚠️ 有优先权的以**优先权日**为准——用申请日会导致现有技术范围错判，这是最高频错误。

3. **新颖性判定**（法22.2）
   输入：权利要求特征集 vs 单份对比文件 → 输出：是否被**单独一份**文件全部公开 + 是否存在**抵触申请**（E类/R类）。
   判定口径：**单独对比**，禁止把多份文件拼起来否定新颖性（那是创造性的活）。

4. **创造性判定**（法22.3 + 三步法）
   输入：最接近现有技术 + 区别特征 → 输出：三步法三段结论。
   ① 确定最接近的现有技术 ② 确定区别特征和实际解决的技术问题 ③ 判断是否显而易见。
   攻击点自查：区别特征是否为惯用手段直接置换 / 技术效果是否可预期 /
   是否存在"事后诸葛亮"（反制：效果须源于区别特征且不可预期）。

5. **实用性与形式合规**（法22.4 + 第八节自查表）
   输入：说明书 + 权利要求书 → 输出：实用性结论 + 形式缺陷清单。
   必查 6 项：从属未引独立（细则20.3）/ 多项引多项（细则22禁止）/ 术语与说明书不一致（细则19.3）/
   附图含文字 / **摘要>300字（细则23）** / 说明书引用权利要求。

## 三、对比文件分级决策树（scout 必用，防漏 E 类）

🔴 **2026-10-14 修正（实测暴露）**：早期版本首节点直接问「公开日 ≤ 申请日？」，
导致 **P 类在逻辑上永不可达**——因为 P 的定义区间（优先权日~申请日）本身就满足"≤申请日"，
会被首节点提前截走判成 X/Y。实测案例（优先权日 2024-12-01 / 公开日 2025-03-01 / 申请日 2025-06-01）
正是被错引到 Y 分支。**必须先确定时间边界，再判类型。**

```
① 有时间边界吗？
   有优先权日 → 边界 = 优先权日（★不是申请日，用错则整轮结论作废）
   无优先权日 → 边界 = 申请日

② 该文件公开日 ≤ 边界？
   ├─ 否（公开晚于边界）
   │   ├─ 公开日 ≤ 申请日（有优先权时）→ P（介于优先权日与申请日之间·视情形）
   │   │   ⚠️ 优先权成立 → 该文件不构成现有技术；优先权不成立 → 可能构成。
   │   │      结论前必须确认优先权是否成立（见检查点 C2）
   │   └─ 公开日 > 申请日，且其申请日在前 → E（抵触申请·高）
   └─ 是（公开早于/等于边界 → 属现有技术）
       ├─ 单独一份即可否定新颖性或创造性？→ X（最高威胁）
       ├─ 需与其他文件组合才能否定创造性？→ Y（高·**必须标注组合对象**）
       ├─ 他人就同样发明在申请日前已提交？→ R（高·程序性）
       └─ 以上皆否 → A（背景技术·低）

③ E 类检索结论必须显式给出（有 / 无 / 未检索），不得静默省略
```

**两个高频坑**：
1. **用申请日当边界**（有优先权时）：会把本不构成现有技术的文件错判成 X/Y，整轮新颖性/创造性结论作废。
2. **漏 E 类**：scout 常只检索已公开文献，漏掉"申请在前、公开在后"的抵触申请。

⚠️ **速查表未覆盖项**（禁止凭记忆延展，须标注"需外部核验"）：
- 享有优先权时，**E 类与 P 类的时间基准如何认定** —— `references/patent-law.md` §一第 7 行与 §五 E 行
  均只使用"申请日"表述，未说明优先权情形
- 优先权成立的要件与法条号

## 四、检查点（关键决策前必须停下确认）

| # | 检查点 | 不确认的风险 |
|---|---|---|
| C1 | 客体排除项判定为"是"时 | 后续三性全判定白做，浪费整轮检索 |
| C2 | 有优先权日但未确认时 | 现有技术时间边界错 → 新颖性/创造性结论整体失效 |
| C3 | 对比文件分级出现 X 或 E 时 | 直接决定方案是否可申请，必须与用户确认再推进 Phase 4 |

## 五、边界与异常恢复

| 异常 | 恢复路径 |
|---|---|
| 引用文件里查不到对应法条 | **标注"本法条未在速查表内，需外部核验"**，禁止凭记忆补法条号 |
| 同一事实两份文件冲突 | 以 `references/patent-law.md` 为准；仍冲突则**并行列出两种结论并标[存疑]**，不擅自取舍 |
| 费用/周期数据与当前政策不符 | 速查表为 2026-08 快照，**费用与周期必须标注"截至 2026-08，需复核现行标准"** |
| 技术方案跨法域（PCT/US/EPO） | 明确声明"本 skill 仅覆盖中国专利法"，**不套用中国法条做他国判定** |
| 无法判断显而易见性 | 输出"无法判定 + 缺什么信息"，**禁止给模糊结论**（如"可能具备创造性"） |

## 六、输出格式契约

判定结论必须逐条包含四要素，缺一不可：
`法条号` + `判定结论（是/否/无法判定）` + `依据（引自速查表哪一节）` + `待补信息`。

- 禁止出现"大概""可能""应该"等模糊表述（与 G5 门禁一致）
- 无法判定的条目必须写清**缺什么信息才能判定**，不得留空
